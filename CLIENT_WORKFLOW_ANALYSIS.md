# Client workflow analysis

Source: the three sample files the client sent (`20261028 PUROK LEADERS.xlsx`, `card layout final.cdr`, `guide (2).cdr`).
They are confidential. They live in `clients/`, which is git-ignored, and were removed from the local Git history. This document
describes **structure only**: no names, addresses, control numbers or other cell contents appear here, in logs, in test fixtures or in screenshots.
All automated tests use synthetic data and synthetic templates generated by `scripts/make-sheet-template.ps1`.

Analysis tools (private, not committed data): `scripts/analyze-template.ps1` writes a *redacted* structural dump (letters → `A`/`a`, digits → `9`) to the git-ignored `private/` folder;
`tests/.private/client-xlsx.test.ts` prints aggregate counts of the workbook only.

## 0. Status of the samples (updated)

The client has confirmed that these three files are their **final** references. CardForge does not redesign anything: it keeps the supplied A4 2 × 5 arrangement, artwork, fonts, sizes, alignment and captions, works only on private copies, and treats the discrepancies in section 4 as review items for the client.
Both templates are supported independently (each is imported, prepared, mapped and generated on its own). Both layouts hold **10** cards (2 × 5); 8-up is only a setting the operator may choose.

## 2. The CorelDRAW templates

Both files: **one page, A4 portrait (210 × 297 mm)**, saved by CorelDRAW; read here with v27.2. Every text object is **unnamed**.

### `card layout final.cdr`

* **10 card positions: 2 columns × 5 rows** (not 8). Column edges at roughly 16–64 mm and 113–160 mm; the five rows are about 56.6 mm apart.
* Shapes on the page: 20 text objects, 20 curves (the static captions "ADDRESS:" and "CONTROL NO.:" are converted to curves), 19 guidelines and 2 groups.
* Per card, two **artistic text** objects:
  1. the person's name, Arial 9 pt, one line;
  2. **one composite object** holding the address and the control number on separate lines, Segoe Print 11 pt, three lines (address, a spacer line, control number), aligned under the curve captions with leading spaces (2 and 9 spaces). Replacing the whole text therefore must keep that padding.
* No mixed formatting inside either text object.
* The sample text in the template belongs to a different list than the spreadsheet (control number prefix in the template differs from the prefix in the data).

### `guide (2).cdr`

* Also **10 positions (2 × 5)**.
* Shapes: 50 text objects, 16 guidelines, 1 group.
* Per card, five text objects: name (Gotham Black 9 pt), address, **precinct number**, control number (Gotham Medium 8 pt) and one text object holding the three static captions (`ADDRESS:` / `PRECINCT NO:` / `CONTROL NO.:`), placed in a group.
* **There is no precinct column in the spreadsheet.** CardForge never invents values: that field is left blank unless the client supplies the data.
* Gotham is a commercial font. It must be installed on the production PC; otherwise CorelDRAW substitutes another font and text widths change.

## 3. Variable fields and mapping decisions

| Template text | Excel column | Notes |
|---|---|---|
| name object | `FULL NAME` | one line |
| address line of the composite object | `ADDRESS` | leading padding kept |
| control line of the composite object | `CONTROL NO.` | leading padding kept; value printed exactly as in Excel |
| precinct (guide only) | none | blank; needs client data |
| `BIRTHDATE` | not placed on either template | only mapped if an approved template needs it |

Rules implemented: captions are kept as designed; any data line without a mapped column prints **blank** (never the template's sample text); a mapped column that is empty for a record prints blank.

## 4. Discrepancies to confirm with the client

1. **Cards per sheet: the brief says 8 (2 × 4); both supplied layouts have 10 (2 × 5).** 40,897 records is not a multiple of 10 or 8. CardForge detects the grid from the template and lets the operator choose how many positions to use; it defaults to the detected 10. The client must confirm which layout is final.
2. **Control-number prefix.** The template sample shows a different prefix from the spreadsheet. CardForge does **not** convert it. It blocks generation until the operator confirms the spreadsheet value with the client (a recorded acknowledgement in the saved mapping).
3. **Precinct number** exists only on the `guide` layout and has no data source.
4. **Birthdate** column has no placement on either layout.
5. **Fonts**: Gotham (guide) and Segoe Print (layout) must exist on the production PC.
6. **File naming and batch size**: 4,090 sheets as one file is impractical; see `LARGE_BATCH_TEST_REPORT.md` for the recommended sheets-per-file.
7. **X7**: everything above was read and rendered with CorelDRAW 27. X7 behaviour is unverified.

## 5. What this means for the product

The existing model (one named-object template, one output file per record) does not fit. The adaptation:

* detect the repeated cards of an unnamed template from object positions, **without** asking the client to rename dozens of objects;
* name the objects in a **private working copy** (`template.cdr` in the app library; the client's original and an untouched `template.original.cdr` are kept);
* map one reference card to columns, line by line, and replicate it to every position;
* fill one record per position, N records per A4 sheet, and several sheets per output document.

## 6. Findings from running the real templates (CorelDRAW 27.2, synthetic data)

* Both templates are detected as exactly **2 columns × 5 rows = 10 cards**, with **no layout warnings**.
* `card layout final.cdr`: 2 variable text objects per card (name; one composite object holding the address and the control number on separate lines). `guide (2).cdr`: 4 variable text objects per card plus one caption group per card.
* **Both templates use the Gotham font family** (Black and Medium). It is **not installed on the development PC**, and CorelDRAW then substitutes it silently (Gotham Medium → Segoe Print, with text extents up to ≈ 2 mm different). CardForge now warns (mapping screen, Generate screen, job report). Gotham **must** be installed on the production PC; without it the output does not match the client's design. This could not be verified with the real fonts here.
* Control-number prefix: the layout template's sample prefix differs from the spreadsheet's `PL` (flagged, generation blocked until the operator confirms; nothing converted). The guide template's sample control number has no prefix, so no warning.
* Precinct (guide) has no data column: it prints blank unless the client supplies data and the operator maps it. Birthdate has no placement on either template and is not mapped.
* Copying a sheet page reproduces the client's artwork **pixel for pixel** (0 differing pixels at 100 dpi for both templates).
* Records on a filled sheet change only the text areas: 0 differing pixels outside the text objects' areas for both templates.
* Typical-length synthetic values (30-character names, 35-character addresses) produced **no clipping or card-crossing warnings** in either template.
